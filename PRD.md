# PRD — Кредитный аналитик
### Система анализа целесообразности финансирования бизнес-проектов

**Версия:** 1.1 (draft)
**Дата:** 07.11.2026
**Статус:** v1.0 реализована и проверена; v1.1 — в разработке

---

## 1. Обзор продукта

Веб-приложение для кредитного анализа бизнес-проектов: расчёт финансовых коэффициентов, инвестиционных показателей, рейтинга и вероятности дефолта, а также автоматическое формирование заключения о целесообразности финансирования.

**Проблема.** Оценка кредитных заявок требует однотипных расчётов по отчётности, сверки с нормативами и отраслевыми бенчмарками, учёта сегмента заёмщика и рыночного контекста. Всё это делается вручную в Excel, медленно и с риском ошибок.

**Решение.** Единый инструмент: вводишь данные заёмщика и параметры кредита — получаешь расчёт коэффициентов с нормативами, скоринговый балл, кредитный рейтинг, вероятность дефолта (PD), отраслевое сравнение, новостной контекст и готовое текстовое заключение с вердиктом.

**Целевая аудитория.** Кредитные аналитики банков, МФО и лизинговых компаний; финансовые директора и собственники бизнеса, оценивающие шансы на финансирование; консультанты по корпоративным финансам.

---

## 2. Цели и критерии успеха

| Цель | Метрика успеха |
|---|---|
| Сократить время первичной оценки заявки | ≤ 15 минут от ввода данных до заключения |
| Стандартизировать методику | Все расчёты по единой задокументированной модели |
| Прозрачность решения | Каждый балл скоринга и PD объясним и воспроизводим |
| Актуальность рыночного контекста | Отраслевые бенчмарки и новости обновляются автоматически ≥ 1 раза в неделю |

**Не является целью:** замена решения кредитного комитета, учёт залогового обеспечения в денежной оценке, интеграция с бюро кредитных историй (вне рамок текущих версий).

## 3. Архитектура и ограничения среды

### 3.1. Реализованная версия 1.0

Один автономный HTML-файл (`credit-analyzer.html`, ~57 КБ): вся логика и данные — в браузере, без сервера. Открывается двойным кликом, работает офлайн, проекты хранятся в `localStorage`. Экспорт отчёта — через печать в PDF.

### 3.2. Целевая платформа v1.1 — GitHub Pages (статический хостинг)

Пользователь выбрал размещение на GitHub Pages. Из этого следуют жёсткие ограничения:

- **Нет бэкенда.** GitHub Pages отдаёт только статические файлы — никакого серверного кода, базы данных, планировщика.
- **Секретные API-ключи невозможны.** Всё, что встроено в страницу, видно всем. Значит, используются только открытые источники данных без авторизации (или пользователь вводит собственный ключ в настройках).
- **CORS.** Прямые запросы из браузера к сторонним сайтам (ЦБ РФ, РБК и т.п.) часто блокируются. Обход — данные подготавливаются заранее и коммитятся в репозиторий.

**Решение — паттерн «статический сайт + GitHub Actions как бэкенд»:**

```
┌─────────────────────────────────────────────────────────┐
│ GitHub-репозиторий                                      │
│                                                         │
│  .github/workflows/update-data.yml  ──► по расписанию   │
│         │                                (еженедельно)  │
│         ▼                                               │
│  scripts/update_data.py             ──► собирает:       │
│                                         • ключевую      │
│                                           ставку ЦБ РФ  │
│                                         • новости по    │
│                                           отраслям (RSS)│
│                                         • отраслевые    │
│                                           бенчмарки     │
│         │                                               │
│         ▼                                               │
│  data/benchmarks.json, data/news.json ──► коммит в репо │
│                                                         │
│  index.html + app.js + styles.css   ──► фронтенд,       │
│                                         загружает JSON  │
└─────────────────────────────────────────────────────────┘
                    │
                    ▼ GitHub Pages
              Пользователь в браузере
```

- Фронтенд остаётся статическим SPA и читает свежие JSON-файлы обычным `fetch` (тот же origin — CORS не мешает).
- GitHub Actions запускает скрипт обновления по cron-расписанию и коммитит результат. Это даёт «автообновление без сервера».
- При локальной работе (файл открыт напрямую) используются вшитые значения по умолчанию с пометкой о дате актуальности.

### 3.3. Технологический стек

| Слой | Выбор | Обоснование |
|---|---|---|
| Фронтенд | Ванильный HTML/CSS/JS, без сборки | GitHub Pages отдаёт файлы как есть; нулевая сборка = нулевой порог для деплоя |
| Графики | Inline SVG (собственные функции) | Уже реализовано, нет зависимостей |
| Хранение проектов | `localStorage` браузера | Достаточно для одиночного пользователя; серверной БД на Pages нет |
| Обновление данных | Python 3 + GitHub Actions (cron) | Python экосистема для парсинга/RSS; Actions бесплатен для публичных репозиториев |
| Источники данных | cbr.ru (XML ключевой ставки), RSS-ленты отраслевых СМИ, вшитые бенчмарки | Открытые, без ключей |

## 4. Функциональные требования

### 4.1. Ввод данных (реализовано v1.0)

**Входные блоки:**

- Проект: название, отрасль (в v1.1 — выбор из справочника), дата анализа, горизонт планирования (3–10 лет), ставка дисконтирования.
- Параметры кредита: сумма (тыс. ₽), ставка (% годовых), срок (мес.), тип графика — аннуитетный или дифференцированный.
- Баланс: денежные средства, дебиторская задолженность, запасы, прочие оборотные активы, внеоборотные активы, краткосрочные и долгосрочные обязательства, собственный капитал.
- ОПиУ: выручка, себестоимость, операционные расходы, амортизация, проценты к уплате, чистая прибыль.
- Прогноз денежных потоков проекта по годам.

**Валидация:** контроль сходимости баланса (активы = обязательства + капитал, допуск 1 %), предупреждение в интерфейсе при расхождении. Пустая форма не выдаёт вердикт «риск», а сообщает «нет данных».

### 4.2. Расчётные модули (реализовано v1.0)

- **Кредитный калькулятор:** график платежей (аннуитет/дифференцированный), годовое долговое обслуживание.
- **Коэффициенты кредитоспособности (12 шт.):** ликвидность текущая/быстрая/абсолютная, автономия, долг/капитал, обеспеченность собственными оборотными средствами, ROA, ROS, долг/EBITDA (с учётом запрашиваемого кредита), покрытие процентов, DSCR по годам (средний взвешенный, минимальный).
- **Инвестиционные показатели:** NPV, IRR (бисекция), индекс доходности PI, простой и дисконтированный срок окупаемости.
- **Скоринг 0–100:** 13 взвешенных факторов, каждый оценивается 0/1/2 относительно нормативов; отсутствующие данные = 0 баллов.
- **Вердикт:** ≥ 70 — «финансирование целесообразно»; 50–69 — «возможно при дополнительных условиях» (поручительства, ковенанты по DSCR, снижение суммы/срока); < 50 — «не рекомендуется».
- **Текстовое заключение:** автоматические выводы по блокам (ликвидность, устойчивость, рентабельность, DSCR, NPV/IRR, окупаемость, сходимость баланса) с цветовой индикацией.

**Калибровки DSCR:** среднее считается по годам с непогашенным долгом, значения обрезаются в диапазон [−1; 3] для устойчивости к выбросам.

### 4.3. Сегментный анализ (v1.1)

**Классификация заёмщика** (по НК РФ / ФЗ-209, упрощённо, с возможностью ручной корректировки):

| Сегмент | Выручка, млн ₽/год | Численность, чел. |
|---|---|---|
| Микро | ≤ 120 | ≤ 15 |
| Малый | ≤ 800 | ≤ 100 |
| Средний | ≤ 2 000 | ≤ 250 |
| Крупный | > 2 000 | > 250 |

**Различия подходов по сегментам:**

| Параметр | Микро/малый | Средний | Крупный |
|---|---|---|---|
| Вес ликвидности в скоринге | Повышен (×1.3) | Базовый | Понижен (×0.8) |
| Вес устойчивости/капитала | Понижен (×0.8) | Базовый | Повышен (×1.2) |
| Вес качества отчётности (качественный фактор) | Высокий — типично «серая» отчётность | Средний | Низкий |
| Норматив текущей ликвидности | ≥ 1.5 | ≥ 2.0 | ≥ 2.0 |
| Норматив автономии | ≥ 0.4 | ≥ 0.5 | ≥ 0.5 |
| Норматив долг/EBITDA | ≤ 3 | ≤ 3 | ≤ 2.5 |
| Базовая PD при одинаковом рейтинге | Надбавка +1.5 п.п. | Надбавка +0.5 п.п. | База |
| Отраслевые бенчмарки | По сегменту, где есть данные | По отрасли | По отрасли |

Обоснование: у микробизнеса волатильность выше, отчётность менее надёжна, поэтому жёстче требования к PD и выше вес операционной ликвидности; у крупного бизнеса решающее значение имеют структура капитала и долговая нагрузка.

### 4.4. Отраслевой анализ и рыночные бенчмарки (v1.1)

**Справочник отраслей** (редактируемый JSON, `data/benchmarks.json`), минимум 8 отраслей на старте:

- Производство, Оптовая и розничная торговля, Строительство, Транспорт и логистика, IT и связь, Сельское хозяйство, Услуги, Общепит и гостиницы.

**Для каждой отрасли хранятся медианные рыночные значения:** текущая ликвидность, автономия, рентабельность продаж (ROS), долг/EBITDA, оборачиваемость дебиторки (дни), типичный DSCR, уровень ставок по кредитам.

**Вывод сравнения:** таблица «показатель заёмщика vs медиана отрасли» с отклонением в процентах и цветовой индикацией (лучше/в пределах нормы/хуже отрасли), плюс текстовый вывод («рентабельность ниже отраслевой медианы на 40 % — признак слабой конкурентной позиции»).

**Источники бенчмарков:** экспертная калибровка на базе открытой статистики (Росстат, отраслевые обзоры), обновление скриптом; в настройках — ручное переопределение любого значения.

### 4.5. Новостной блок (v1.1)

- GitHub Actions еженедельно собирает заголовки из RSS-лент деловых СМИ (РБК, Коммерсантъ, Ведомости — отраслевые разделы) по ключевым словам отраслей из справочника.
- Результат — `data/news.json`: массив `{отрасль, заголовок, ссылка, дата, источник}`, до 10 свежих на отрасль.
- На странице анализа показывается блок «Рыночный контекст»: новости по отрасли заёмщика с датами и ссылками; при отсутствии свежих — пометка о дате последнего обновления.
- Новости носят информационный характер и **не влияют** на скоринг (это фиксируется в дисклеймере).

### 4.6. Кредитный рейтинг и вероятность дефолта (v1.1)

**Мастер-шкала** — скоринговый балл переводится в буквенный класс с калиброванной годовой PD (по мотивам практики рейтинговых агентств и банковских внутренних шкал для корпоративного сегмента РФ):

| Класс | Балл скоринга | Описание | Базовая PD, год | С надбавкой микро | сегмента |
|---|---|---|---|---|---|
| AAA | 90–100 | Исключительная надёжность | 0.1 % | +0.0 п.п. | |
| AA | 82–89 | Очень высокая | 0.3 % | +0.1 | |
| A | 74–81 | Высокая | 0.7 % | +0.2 | |
| BBB | 66–73 | Хорошая, инвестиционная | 1.5 % | +0.4 | |
| BB | 58–65 | Удовлетворительная | 3.0 % | +0.8 | |
| B | 50–57 | Ниже среднего, спекулятивная | 6.0 % | +1.5 | |
| CCC | 40–49 | Существенный риск | 12 % | +2.5 | |
| CC | 30–39 | Высокий риск дефолта | 22 % | +4.0 | |
| C | 20–29 | Крайне высокий риск | 35 % | +5.0 | |
| D | < 20 | Дефолт/преддефолтное состояние | 60 % | — | |

**Корректировки PD:**

- Сегментная надбавка (таблица выше).
- Отраслевая корректировка: отрасли из «рискованного» списка (строительство, общепит) ×1.3; «стабильные» (IT, услуги) ×0.9.
- Модификатор DSCR: средний DSCR < 1.0 — PD ×1.5; DSCR ≥ 1.5 — PD ×0.8.
- Итоговая PD ограничена диапазоном [0.05 %; 99 %].

**Отображение:** карточка рейтинга рядом с вердиктом (класс крупно, цвет по зоне: инвестиционная/спекулятивная/дефолтная), PD в процентах, шкала с позицией заёмщика, перечень применённых корректировок, ожидаемые потери EL = PD × LGD × EAD (LGD = 45 % по умолчанию, редактируется; EAD = сумма кредита).

**Дисклеймер:** PD — оценочная, калибрована на типовых уровнях рынка, не обучена на портфеле конкретного банка; для боевого использования требуется бэк-тестирование на исторических дефолтах.

### 4.7. Отчётность и сохранение

- Печатная версия отчёта (Ctrl+P → PDF): шапка с вердиктом и рейтингом, все таблицы и заключение, без элементов навигации.
- Сохранение проектов в `localStorage`: список с датой, оценкой и рейтингом; открытие/удаление; кнопка «Новый проект».
- Демо-режим: кнопка «Пример с данными» (производственная компания, кредит 15 млн ₽ под 19 % на 5 лет, итог 90/100, рейтинг AAA) — для мгновенной демонстрации.

## 5. Нефункциональные требования

- **Производительность:** полный расчёт < 50 мс; первый экран < 1 с на среднем канале (файл < 100 КБ без учёта JSON-данных).
- **Совместимость:** Chrome/Edge/Firefox последних двух версий, Safari 16+; адаптивность от 360 px.
- **Доступность:** навигация с клавиатуры (табы — `role=tablist`), видимый фокус, контраст ≥ 4.5:1 для текста, `prefers-reduced-motion`.
- **Приватность:** данные проектов не покидают браузер пользователя; новостной JSON содержит только публичные заголовки.
- **Надёжность данных:** при недоступности свежего JSON — вшитые дефолтные значения с видимой датой актуальности.

## 6. Методология расчётов (справочно)

**Аннуитетный платёж:** `P = S · i · (1+i)ⁿ / ((1+i)ⁿ − 1)`, где i — месячная ставка.

**NPV:** `Σ CFt / (1+r)ᵗ`, CF₀ = −сумма кредита. **IRR:** корень NPV = 0, бисекция на [−0.99; 10].

**DSCR (год y):** `CF_y / (платежи по кредиту в году y)`; средний — по годам с долгом > 0, значения обрезаны в [−1; 3].

**Окупаемость (дисконт.):** первый год t, где накопленный дисконтированный поток ≥ сумме кредита; внутри года — линейная интерполяция.

**Скоринг:** `100 · Σ(баллᵢ · весᵢ) / Σ(2 · весᵢ)`, баллᵢ ∈ {0, 1, 2} по нормативам сегмента.

**EL (ожидаемые потери):** `PD · LGD · EAD`.

Полный перечень нормативов и весов — в разделе 4, в коде вынесены в редактируемую конфигурацию.

## 8. Риски и допущения

| Риск | Влияние | Митигация |
|---|---|---|
| RSS-источники меняют формат или закрываются | Новости перестают обновляться | Fallback на вшитые данные + пометка даты; несколько источников |
| GitHub Actions задерживает cron-запуски | Данные стареют | Пометка даты обновления; ручной запуск workflow |
| PD не калибрована на портфеле пользователя | Неточные уровни дефолта | Явный дисклеймер; редактируемая мастер-шкала; рекомендация бэк-теста |
| Отраслевые бенчмарки — экспертная оценка | Споры по отдельным значениям | Ручное переопределение в настройках, указание источника |
| localStorage ограничен (~5 МБ) | Мало места при сотнях проектов | Экспорт/импорт проектов файлом (backlog) |

**Допущения:** пользователь работает с российской отчётностью в тыс. ₽; качественные факторы (менеджмент, залоги, судебные споры) оцениваются кредитным специалистом вне системы; ставка дисконтирования задаётся пользователем (рекомендация: ставка кредита + премия 3–7 п.п.).
